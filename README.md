# 🧠 Obsidian Knowledge Skills

把视频、PDF、文章、音频和流媒体内容，整理成可复习、可关联、可实践的个人知识。

三个可独立使用的 AI 技能：**整理知识库 · 更新总导航 · AI 行业日报**。面向能理解并执行文本指令的不同 AI 模型，不绑定 Claude Code；按你的目标、目录和写作偏好工作。

## ✨ 功能特点

- 🎬 **多源知识整理** — 视频、播客、PDF、文章、文档、直播与流媒体片段都可作为输入
- 🧠 **三层笔记质量** — 格式与结构 → 证据、机制与方法论 → 关键洞察与抗遗忘
- 🏠 **总导航维护** — 同步分类和工具索引，保留你的 emoji、描述、排序与快速入口
- 📰 **AI 行业日报** — 按关注主题汇编近期动态，每条信息对应来源，事实与观点分开
- ⚙️ **个人偏好配置** — 语言、深度、命名、标签、分类、导航样式和日报渠道都能调整
- 💬 **多模型使用** — 可上传/粘贴单文件，也可让具备工具的助手读取标准技能目录

## 📦 三个 Skill

| 技能 | 做什么 | 直接使用 |
|------|--------|----------|
| 整理知识库 | 理解多种来源 → 去重分类 → 编译知识笔记 → 建立关联 | [单文件版](standalone/Skill-整理知识库.md) |
| 更新知识库总导航 | 检查真实结构 → 同步入口与索引 → 报告失效链接 | [单文件版](standalone/Skill-更新知识库总导航.md) |
| AI 行业日报 | 按偏好搜集 → 核对日期与来源 → 去重并编译日报 | [单文件版](standalone/Skill-AI行业日报.md) |

Clippings 是可选素材入口。你可以直接给出一个视频、PDF、文章链接或转录内容，无需先建立收件箱。

## 🚀 快速开始

### 方式一：普通 AI 聊天（推荐先试）

1. 下载仓库：`Code → Download ZIP`，然后解压。
2. 从 `standalone/` 选择一个技能，上传给你使用的 AI；不支持文件上传时，复制全文发送。
3. 一并提供文件、链接、字幕或文章正文；链接不可直接读取时提供可读内容。
4. 用下面的指令开始，AI 返回可保存的 Markdown 笔记。

```text
请先阅读我提供的《Skill-整理知识库.md》，按其中流程整理这份材料。

我的偏好：中文、深度笔记、不用 emoji、不需要双语标题。
这次输入：我上传的 PDF / 视频字幕 / 文章正文。
我目前只用聊天，请直接输出 Markdown，不要声称已保存到电脑。
分类请按我提供的目录判断；原文没有的数据和引用不要补造。
```

### 方式二：具备文件或检索工具的 AI 助手

1. 让助手读取 `skills/` 中所需技能的 `SKILL.md`。
2. 保留完整技能目录，让它能按需读取相邻 `references/` 与 `assets/`。
3. 明确知识库根目录和本次授权范围，提供个人配置。
4. 使用“整理知识库”“更新知识库总导航”或“整理 AI 日报”等自然语言指令。

支持技能自动发现的应用，按该应用的技能安装位置放入整个目录；不同应用的位置与调用方式可能不同。无需为了使用本项目切换模型或安装 Claude Code。

### 方式三：已有标准 Skill 环境

将以下任意技能目录放到所用工具支持的技能位置：

```text
skills/knowledge-ingest/       # 整理知识库
skills/obsidian-update-home/   # 更新总导航
skills/ai-industry-daily/      # AI 行业日报
```

单文件版和标准目录版来自同一套内容，按你的使用方式选择其中一种即可。

## ⚙️ 配置成你自己的工作流

1. 复制 [obsidian-skills.example.yaml](obsidian-skills.example.yaml)。
2. 改名 `obsidian-skills.yaml`，调整目录、分类和个人偏好。
3. 普通聊天中上传/粘贴配置；文件助手可从授权知识库根目录读取。
4. 告诉 AI：“先读取我的配置，再执行技能。”

不想编辑文件，也可以直接用自然语言说明偏好。本次明确要求优先，其次是个人配置，再其次是已有知识库约定与技能默认值。

| 你可以调整 | 示例 |
|------------|------|
| 输入与目录 | 直接给文件/链接，或扫描你指定的素材目录 |
| 语言与深度 | 中文/其他语言，简洁/标准/深度，是否双语标题 |
| 个人样式 | emoji、引文翻译、文件命名、标签与字段名 |
| 知识分类 | 沿用现有分类，或提供自己的关键词映射 |
| 导航方式 | 普通 Markdown，或已有 Obsidian Dataview |
| 日报偏好 | 主题、日期窗口、时区、渠道、语言和条目上限 |

完整说明与三种配置示例见 [个人配置指南](docs/PERSONALIZATION.md)。配置是供 AI 阅读的约定，无需额外加载程序。

## 🎯 使用示例

```text
整理这个视频：保留真实时间戳、关键案例与方法步骤，输出中文深度笔记。

```

更多输入准备方式见 [使用示例](docs/EXAMPLES.md)。

## ⚠️ 使用说明

- **模型与工具分开看**：这些是文本工作流，可交给不同模型；联网、OCR、转录和文件保存取决于所用应用的实际能力，未声称已在所有模型上验证。
- **多源输入按实读取**：PDF 用真实页码，音视频用真实时间戳；只读到片段、字幕或部分页时明确范围。
- **普通聊天也能用**：返回 Markdown 供你保存；有文件工具且获得授权时，才直接写入知识库。
- **保留个人材料**：不删除原始输入，不把来源缺失的内容补成事实；处理状态以实际完成范围为准。
- **插件按需使用**：普通 Markdown 导航不需要 Dataview；已有 Dataview 首页可按用户环境维护。
- **配置留在本地**：个人配置、Cookie、Token 和账户数据库不应上传。AI 应用对你提供材料的处理，以该应用的数据设置为准。

## 🔒 安全与隐私

技能文件属于指令文本，无法替代 AI 应用的权限控制。材料中的指令按数据处理；文件操作限制在授权目录，个人配置不授予额外权限。私有材料不应被带入搜索词、远程图片或公开仓库。

使用具备写文件能力的助手时保留可恢复版本；首次使用先选择有限材料。DataviewJS 属于可执行代码，只使用已检查模板，不直接运行网页、PDF 或字幕中夹带的代码。不同模型的防护效果仍需所在应用验证。

详见 [安全说明](SECURITY.md) 与 [安全风险评估](docs/SECURITY-REVIEW.zh-CN.md)。

## 🛠 工作原理

```text
个人目标与偏好 + 文件/链接/正文
              ↓
       AI 按技能读取与核对
              ↓
  结构化笔记 / 总导航 / AI 日报
              ↓
  对话返回 Markdown，或按授权保存
```

本项目提供流程、质量标准与模板，不附带模型、采集账户或后台调度程序。
