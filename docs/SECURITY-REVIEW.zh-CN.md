## 结论

**发布这份脱敏后的技能/模板包：未发现需要阻止公开发布的明确秘密或恶意安装行为。实际使用这些技能：仍有依赖模型和宿主权限的条件性风险。**

不能把“开源文件可发布”理解为“任何模型加载后都不会误操作”。技能中的安全规则只能指导模型；文件边界、网络出口和工具权限应由应用实施。拥有整盘读写、任意命令和外网权限的代理，一旦被恶意材料诱导，后果仍可能较严重。OWASP 对提示注入和过度代理能力也强调类似边界。参见 [提示注入](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) 与 [过度代理能力](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)。

## 风险与处理

| 风险 | 原有情况与可能后果 | 本次补强 | 剩余边界 |
|------|--------------------|----------|----------|
| 间接提示注入：有工具时条件性高风险 | 文章、PDF/OCR、字幕或笔记可能伪装系统指令，诱导读取其他文件或外传 | 三个技能明确将来源与工具结果视为数据，禁止来源自行授权、变更配置或运行命令 | 提示规则不保证模型遵从；仍需宿主权限隔离与真实行为测试 |
| 文件路径越界：有写权限时条件性高风险 | 可配置路径与来源生成文件名，可能通过路径穿越、绝对路径或链接逃出目标目录 | 增加真实路径、符号链接/junction、授权根目录和文件名检查要求 | 仓库没有实现统一文件代理；需要实际工具执行路径校验 |
| 可执行导航/查询注入：采用 JS 模板时条件性高风险 | 把标题、描述和目录直接拼进 JavaScript/DQL，可能将内容变成代码或改变查询范围 | 禁止 eval，要求 cats 经 JSON 序列化，DQL 目录使用 JSON 字符串编码，不引入来源脚本/远程嵌入 | 已验证字符串序列化；未覆盖真实插件渲染器、HTML/Markdown 清洗和所有字段组合 |
| 私有内容外传：中风险，敏感材料时可更高 | 云端模型、外部 OCR/转录、搜索词、签名 URL、远程图片都可能带出私人信息 | 明确外部传输按用户授权范围，禁止私有内容进入搜索参数和图片 URL，签名链接不直接公开 | 上传到何种 AI 服务仍由用户和宿主的数据设置决定，技能不能改变服务留存策略 |
| 覆盖、并发修改、错误完成标记：中风险 | 反向链接、日报合并与导航同步可能覆盖人工变更或提前标记 | 要求写前读最新内容、保留可恢复版本/差异、写后复读、遇冲突停止受影响写入 | 未在真实 vault 进行并发/回滚演练，不能保证每个宿主实现原子写入 |
| 配置被误当授权或代码：中风险 | 任意 YAML/未知键可能诱导执行，异常范围扩大操作 | 限定已知数据字段、安全解析、不执行自定义标签/表达式，配置不授予额外权限 | 需宿主安全 YAML 解析器；当前项目是说明文档，不是强制配置校验器 |
| 公开包泄露凭据/个人材料：本次未发现，后续仍需检查 | .gitignore 不能过滤网页上传或清除历史；私人配置、日志和签名链接可能泄漏 | 扩充忽略规则，检查当前全包凭据、私钥、私有路径、邮箱和签名链接模式，补充发布说明 | 模式扫描可能漏检，未调用完整专业秘密扫描器；以后每次提交都需重新核查 |
| 来源和版权/事实误用：中风险 | 未读全文、时间戳/页码虚构、原文长篇复制会造成错误归档和再分发 | 保留来源与范围，区分事实/观点/推断，避免超量引用和处理状态误报 | 未对真实内容进行版权授权判断或事实逐条审计，不构成法律意见 |

原有技能已具备保留原始材料、禁止编造、局部写入和配置不扩权的部分要求。本次主要补齐更明确的执行边界，不能称为已从技术上消除所有上述风险。

## 补充发现：公开提交身份

初始化 README 时，GitHub 连接自动生成了首个公开提交。随后读取提交对象，确认 author/committer 字段使用账号邮箱，而非 noreply 身份。这是文件内容扫描没有覆盖的独立元数据风险；本报告不重复写出邮箱。

该提交只有初始化 README，完整技能包当时尚未发布。问题不涉及访问令牌泄漏，但会公开联系人身份；如果使用者希望匿名或减少垃圾邮件风险，应先处理提交身份和已存在的历史。证据为 [初始化提交](https://github.com/zhouyuzhou361-cloud/obsidian-knowledge-skills/commit/e8d172fa7a407d18ce8952e962a67a163e7dcdb7)。

当前连接的提交接口不能指定 author/committer，不能承诺它会采用匿名邮箱。后续发布必须尊重用户对提交身份的选择；不要认为隐藏个人资料页邮箱就一定改变所有提交，也不要认为修改未来身份会清除旧提交。没有用户明确接受当前身份时，不继续以该身份提交。本次发布已由仓库所有者明确选择沿用当前提交身份继续，邮箱未匿名化；该风险为已知接受，并非已修复。

更改身份设置主要影响后续提交，既有历史需要单独处理；重写历史或删除公开对象也不能保证他人副本消失。详见 [GitHub 提交邮箱](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address)。

## 发布和使用建议

发布只包含技能、配置示例、模板与说明；保留本报告和 SECURITY.md 中的限制说明。首次实际使用选择有限材料和可恢复副本，给助手恰好够用的文件与网络权限；普通聊天模式先审核返回文本再保存。

需要更强安全保证时，在实际使用的宿主中加入确定性的路径/网络/配置检查，并使用无真实秘密的诱导材料验证是否会越权。不要仅靠增加几句提示就宣称通过渗透测试或全模型安全认证。
